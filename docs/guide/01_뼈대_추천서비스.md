# 0 · 1단계 — 뼈대와 추천 서비스: 실습의 함수를 ‘매일 돌아가는 서비스’로

> 실습 U3-P6 의 `recommend()` 는 부르면 답을 만드는 함수였다. 서비스에서는 **미리 계산해 표에 넣고, 화면은 표를 읽는다.**
> 그래서 AI 서버가 잠깐 꺼져도 추천은 보이고, 응답은 표 읽기만큼 빠르다(p95 약 15ms).

## 1. 네 부분과 두 스키마

```
 브라우저 ──▶ Next.js(:3000) ──/api · /oauth2 · /login/oauth2 넘김──▶ Spring Boot(:8080)
                                                                      │  app 스키마(회원 · 피드백 · 기록, Flyway)
                                                                      │  reco.v_svc_* 뷰 읽기 전용
                                                                      └─ X-Internal-Token ─▶ FastAPI(:8000)
                                                                                              │ reco 스키마(수집 · 학습 · 추천)
                                              작업 프로세스(reco.worker) ── 정해진 시각 · 요청 대기열 ─┘
```

| 결정 | 이유 |
|---|---|
| 브라우저는 3000 만 안다 (Next `rewrites`) | 세션 쿠키 · CSRF 가 CORS 없이 동작. 소셜 로그인 redirect_uri 도 3000 하나 |
| Spring 이 FastAPI 를 내부 토큰으로만 부른다 | AI 서버(학습 · 관리 작업)를 밖에 드러내지 않는다. 토큰이 비면 FastAPI 가 503 |
| DB 하나, 스키마 둘 | `reco` = 파이썬 소유(수집 · 학습 · 추천). `app` = Spring 소유(Flyway). 계정도 둘(`reco_ai` · `reco_api`) |
| Spring 은 `reco.v_svc_*` **뷰만** 읽는다 | 두 언어 사이의 약속은 뷰 이름 · 열 이름. 표 구조를 바꿔도 뷰만 지키면 Spring 은 그대로 |
| 무거운 일은 작업 프로세스 | 웹 요청 안에서 학습하지 않는다. 관리자 버튼도 ‘요청’만 남긴다(3단계) |

## 2. 미리 계산 (`ai/reco/precompute.py`)

- 날짜 × 품목마다 **챔피언과 규칙(어제 좋았던 곳) 둘 다** 계산해 `recommendation` 에 권역 14곳의 전체 순위를 저장한다
  → 결과가 확정되면 둘을 같은 날로 채점할 수 있다(5단계 추천 성적).
- `rec_run.served_version` = 화면에 보일 쪽. 모델을 바꿔도 지난날의 화면은 그때 보여 준 그대로 남는다.
- 순위에서 뺀 권역과 이유(`recommendation_excluded`): 철이 아님 — 최근 28일 중 위판한 날이 5일 미만.
- 경고: 해상예보 풍속 14m/s 이상이면 순위는 그대로 두고 경고만 단다. 갈지 말지는 사람이 정한다.
- 근거 문장: 로지스틱의 ‘계수 × 표준화 값’ 이 큰 특성부터 사람 말로(`_reasons`).
- 어제 위판이 평소의 몇 %만 들어왔는지(`yesterday_fill`) — 위판 자료가 며칠에 걸쳐 채워지므로 아침 추천에는 안내를 단다.

## 3. 시연 날짜

`.env` 의 `DEMO_TODAY=2026-10-15` 가 ‘오늘’을 고정한다. 시연 자료가 10/14 까지라 늘 같은 화면이 나오고,
캡처 · 수업 · 점검 결과가 날마다 바뀌지 않는다. 처음 상태는 `python -m reco.jobs run bootstrap_demo` 로 만든다(약 15초):
자료 적재 → reco_v1 (실습 P6 와 같은 방법) → 7/1 ~ 오늘 추천 → 확정된 날 채점.

## 4. Spring 추천 API

| 경로 | 하는 일 |
|---|---|
| GET `/api/meta` | 오늘 · 시연 여부 · 품목 · 추천이 있는 첫날/마지막 날 |
| GET `/api/areas` | 권역 14곳 (이름 · 관측소 · 위경도) |
| GET `/api/recommendations?species&date&k` | 그날 추천: Top-k · 나머지 후보 · 뺀 권역 · 모델 · 최근 8주 성적 · 안내문. 계산 안 된 날이면 `available:false` + 이유 |
| GET `/api/recommendations/history?species&weeks` | 날마다 Top-3 · 좋은 날이었던 권역 · 모델/규칙/무작위 P@3 (5단계 화면) |
| GET `/api/health` | app DB · reco 뷰 · AI 서버를 한 번에 — /status 화면이 읽는다 |
