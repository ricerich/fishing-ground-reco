# 5단계 — 추천 성적 · 피드백 · 이용 기록 · 점검

> 서비스는 ‘맞았는지’를 스스로 보여 줘야 한다. 그리고 사람이 느낀 것(피드백)과 숫자(채점)를 나란히 둔다.

## 1. 추천 성적 (/record)

- 위판 자료가 다 채워지는 **7일 뒤** 결과를 확정하고 채점한다(`evaluate_live`). 그래서 최근 7일은 목록에 없다.
- **P@3** = Top-3 가운데 실제로 좋은 날(평소의 1.5배 이상)이었던 권역의 비율.
- 세 값을 나란히: **보여 드린 추천**(그날 서비스한 모델) · **규칙**(어제 좋았던 곳) · **무작위로 세 곳 골랐다면**(기대값).
- 한 줄 판정: 규칙과의 차이가 2%p 안쪽이면 ‘같은 수준’이라고 그대로 쓴다. 실습 P6 결론과 같다.
- 주별 그림: 한 축(0~100%), 선 두 개 + 무작위 점선, 끝에 이름표, 마우스를 올리면 그 주의 세 값.
  색은 부표 주황(추천) · 파랑 `#1679a8`(규칙) — 색각 이상 검사(dataviz 검증 스크립트) 통과.
- 날마다: Top-3 를 채운 칸(좋은 날)과 테두리 칸(아님)으로, 놓친 좋은 권역까지.

## 2. 추천 피드백

- 회원은 Top-3 카드마다 ‘도움이 됐어요 / 아니에요’. 한 사람 · 하루 · 품목 · 권역에 한 줄(다시 누르면 바뀜).
- **그때 서비스한 모델 버전**을 함께 저장 → 관리자 화면에서 모델별로 모아 본다. 모델을 바꾼 뒤 체감이 나빠졌는지 볼 수 있다.
- API: `GET /api/feedback?date&species` (내 것) · `PUT /api/feedback {date, species, area, helpful, comment?}`

## 3. 관리자 · 이용 기록 (/admin/usage)

| 칸 | 내용 |
|---|---|
| 답 품질 | LLM × 쓰임(물어보기 · 근거 설명)별 답 수 · 인용 정상 · 숫자 정상 · 모른다고 답 · 도움 됨/아님 · 평균 시간 |
| 질문과 답 | 최근 답, ‘문제 있는 답만’(숫자 검사 실패 · 없는 인용 · 아니에요) |
| 추천 피드백 | 모델 × 품목별 도움 됨/아님, 남긴 말 |
| 관리자 행동 | 누가 언제 어떤 작업을 요청했나 (`admin_audit`) |

## 4. 점검 — 한 번에

```bash
scripts/test_all.sh
```

| 단계 | 무엇 | 수 |
|---|---|---|
| AI 단위 테스트 | 학습셋 · 권역 · 추천 · 수집 방식 · RAG 검색/검사 (`ai/tests`) | 25 |
| Spring 단위 테스트 | 소셜 제공자 응답 맞추기 · 비밀번호 규칙 · 토큰 해시 | 11 |
| 화면 단위 테스트 | 숫자 · 날짜 표기 (`web/src/lib/format.test.ts`) | 3 |
| 통합 점검 `check_all.py` | 네 부분 health · 내부 토큰 · 추천 · 속도 · 오류 처리 · 미리 계산=즉석 계산 · 보호 경로 · 회원 흐름 34개 · 관리자 작업 · RAG 스트림 | 13 |
| 화면 E2E `scripts/e2e/e2e.mjs` | 브라우저로: 첫 화면 · 품목 바꾸기 · 성적 · 로그인 · 피드백(새로 고쳐도 유지) · 근거 설명 · 물어보기 · 403 · 로그아웃 · 관리자 · 휴대폰 가로 넘침 | 13 |

E2E 는 Playwright 를 따로 깔지 않고 전역(`npm i -g playwright`)이나 `web/node_modules` 의 것을 쓴다 — 캡처 스크립트와 같다.
